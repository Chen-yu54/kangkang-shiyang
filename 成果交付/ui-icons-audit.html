三个一致性问题
  • 图形来源混了三种：PNG 图标（tabBar/菜系）+ 字体符号（! › × − + ★ ·）+ emoji（👤）。三者渲染机制不同，跨平台表现不一致。
  • 字体符号随系统字形变：› 在 iOS 和安卓微信里的粗细与长度不同；★ 尤其明显，安卓常显示为空心或等宽。
  • 死代码未清：format.js 的 CUISINE_EMOJI 五个 emoji 已经不被任何 WXML 引用（界面全换成 PNG 了），但常量还在。
建议
  • P0 删掉 CUISINE_EMOJI，或保留但注明「仅作降级兜底」，避免后人误以为界面还在用 emoji。
  • P1 ★（价格档次）最该换成图形——它是唯一会在列表中重复出现多次的符号，字形不一致最显眼。可改为 3 个固定尺寸的小 PNG 或 CSS 画的圆点。
  • P2 › 与 × 可保留字体符号（体积为零，视觉上差异可接受）；! 已经是 CSS 圆 + 字符，可继续用。
  • 保留 👤 头像 emoji —— 头像属个人位，等有登录体系再换真实头像。
