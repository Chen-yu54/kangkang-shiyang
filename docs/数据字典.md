# 数据字典

> 三个实体：菜品 / 节气 / 食材卡。字段、枚举白名单、空值情况、以及**字段在显示前的处理规则**。
> 所有内容与 `miniprogram/data/` 及 `miniprogram/packageIngredient/data/` 下的构建产物一致。

---

```
knowledge/                      人工维护的源（团队内容侧产出）

├── 潮汕菜96道_十字段.md

├── ingredients_kb_v0.2.md          食材主料知识库
        │
        │  scripts/build-data.js
        │  scripts/build-ingredients.js
        ▼
miniprogram/data/                 构建产物（前端只读，禁止手改）
├── recipes.js                      288 道菜
├── terms.js                        24 个节气
├── cuisines.js                     4 张风味卡
└── meta.js                         版本元信息

```

**规则**：改内容只改 `knowledge/`，然后重跑构建脚本。直接改 `data/` 下的 `.js` 会被下次构建覆盖。

### ⚠️ `caution` 与 `allergen` 的显示规则（重要）

这两个字段的知识库原文含**疾病名称与诊疗指向**（如"某类人群忌""某项指标偏高者少"）。这些内容不能原样上界面。

**处理方式**：

| 字段 | 怎么处理 | 结果 |
|---|---|---|
| `caution` | **整块不显示**。`dish.js` 注释写明：「知识库里的写法是给编辑看的」 | 界面上看不到 |
| `allergen` | 经 `format.softenCaution()` 净化后显示 | 疾病名被替换成通用表述 |

**净化实例**（`utils/format.js` 的 `SENSITIVE_WORDS` 机制）：

```
原文「某某忌；虾类过敏忌」        → 「慎食；虾类过敏忌」
原文「含盐偏高，某某少；虾过敏忌」  → 「含盐偏高，建议少吃；虾过敏忌」
原文「贝类过敏；某某忌」          → 「贝类过敏；慎食」
```

**这个机制有一个副作用，必须说清**：

净化后只剩「慎食」「建议少吃」，**丢了"为什么"**——用户看到"慎食"不知道慎什么。

这是**有意的取舍**：宁可信息少，也不显示疾病名。如果要做得更好，需要在数据层把限制原因改写成**不含疾病名的正向表述**（如"偏咸，口味清淡的更合适"），而不是靠运行时过滤。

**这件事目前没做**，记在[局限](#五已知限制)里。

## 三、节气（`data/terms.js` · 24 条）

### 完整字段表

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `name` | string | 节气名，唯一 | `立冬` |
| `order` | int | 自然顺序 1–24（小寒起） | `21` |
| `termOrder` | int | 立春起排序 1–24 | `19` |
| `dateWindow` | [string, string] | 日期区间 `MM-DD`，**不是硬编码表** | `["11-07","11-21"]` |
| `season` | enum | 春 / 夏 / 秋 / 冬 | `冬` |
| `intro` | string | 节气简介，已剔除功效表述 | `立冬是冬季的第一个节气…` |
| `ingredients` | string[] | 当令食材 10 种 | `["羊肉","鸡肉",…]` |
| `ingredientDetails` | object[] | 食材 + 性味 + 价格档 | `[{name,nature,priceLevel}]` |
| `slogan` | string | 一句话主旨 | `万物收藏也` |
| `aura` | string | 氛围词 | `初冬清冷` |
| `poem` | object | 诗词 | `{text, author}` |
| `phenology` | string[3] | 三候 | `["水始冰","地始冻","雉入大水为蜃"]` |
| `folk` | object[] | 食俗，标「民间流传」 | `[{title,icon,desc,detail}]` |
| `dishes` | string[] | 关联菜品 id | `[]`（当前为空，反向索引走菜的 `terms`）|

### 节气相关的两个排序

| 字段 | 起点 | 用途 |
|---|---|---|
| `order` | **小寒**（1）→ 大寒（24） | 公历年内顺序，用于日期区间计算 |
| `termOrder` | **立春**（1）→ 大寒（24） | 传统节气顺序，用于季节划分（每 6 个一季）|

**为什么两个都要**：公历 1 月是小寒大寒，但传统节气序列从立春开始。用 `order` 算"今天是哪个节气"，用 `termOrder` 算"属于哪个季节"。

### 跨年边界

`冬至` 的 `dateWindow` 是 `["12-22","01-05"]`，跨年。`format.currentTerm()` 的处理：

```js
if (end < start) end = new Date(y + 1, end.getMonth(), end.getDate());  // 跨年区间
```

年初（01-01 ~ 01-05）无命中时，归属上一年最后一个节气。

## 四、食材卡（`packageIngredient/data/ingredients.js` · 222 张）

### 完整字段表

| 字段 | 说明 | 示例 |
|---|---|---|
| `id` | 标准卡编号 | `ING-A01` |
| `name` | 标准名，与索引表对应 | `猪肉` |
| `oneLine` | 一句话，≤60 字 | `广东人餐桌上的"百搭肉"…` |
| `identity` | 是什么：别名、类别、可吃部分 | `猪肉，又叫豚肉，畜肉…` |
| `origin` | 产地与季节 | `主要产自粤西、粤北，四季都有…` |
| `quality` | **质量与安全**：看外观 / 理化指标 / 安全指标 / 微生物 | `看外观：瘦肉淡红均匀…安全指标：兽药残留、铅镉…` |
| `nutrition` | 主要成分 | `优质蛋白，维生素 B1 在肉类中较高…` |
| `select` | 怎么挑，含口诀 | `色匀、脂白、按回弹，口诀：色匀、脂白、按回弹` |
| `cook` | 怎么处理 | `里脊逆纹切片上浆快炒，五花先煸后炖…` |
| `caution` | 要注意，已过滤疾病名 | `不吃生肉；长者切小炖软` |
| `price` | 价格档与替代 | `价格档 2，替代鸡肉、牛肉、豆制品` |
| `inspect` | **检测与判定**：取样 / 检测方法 / 判定标准（含 GB 号）| `取样：同批次不同部位…按此判定：GB 2707` |
| `basis` | 资料依据 | `CFCT6 第二册，膳食指南 2022，GB 2707…` |

**`quality` 与 `inspect` 是"食品安全"的正面回答**：前者说该看什么指标，后者说按什么标准判定。两者都带国标编号，可核验。

### 主料索引（`ingredientsIndex.js`）

```js
module.exports = {
  INDEX: [{ no, name, type, batch, dishes, cardId }],   // 291 条
  LOOKUP: { '猪肉': 'ING-A01', '姜': 'ING-A27', … },     // 主料名（含别名）→ 卡片 id
  SKIP: ['生抽', '冰糖', …],                             // 调味料，不做溯源
  PREFIXES: ['客家', '增城', '鲜', …],                    // 运行时剥离的前缀
};
```

| 字段 | 说明 |
|---|---|
| `type` | 植物性 / 动物性 / 加工 |
| `batch` | A（1–60）/ B（61–120）/ C（121–291）|
| `dishes` | 该主料在多少道菜里出现 |
| `cardId` | 有标准卡的填 id，没卡的留空串 |

### 匹配机制（覆盖 59.8% 的原因）

菜谱写的主料名与知识库标准名不完全一致，三层匹配：

```
① 直接命中        白灼菜心 → 菜心       ✓
② 别名表（148 条）  姜 → 生姜           ✓
③ 前缀剥离（17 个） 增城菜心 → 菜心      ✓
                   客家梅菜 → 梅菜
                   干香菇  → 香菇
```

**匹配不到就不显示成缺档**：调味料（`SKIP` 表，119 条）直接跳过，不做溯源。

### 覆盖数据

| 项 | 值 |
|---|---|
| 需溯源主料引用 | **928 次** |
| 命中档案 | **555 次（59.8%）** |
| 调味料跳过 | **241 次** |
| 未命中种类 | **272 种** |

**主要缺口**（知识库 v0.2 未覆盖）：薯粉、南姜、乳鸽、客家咸菜、南北杏、响螺、韭黄、章鱼干、咸柠檬、蚝豉。

界面点进去显示：「『薯粉』暂时没有档案。我们只收录有据可查的食材资料，不编内容。」

## 六、怎么复算

```bash
# 菜品规模与结构
node -e "const r=require('./miniprogram/data/recipes.js');console.log(r.length)"

# 每节气菜数（应全为 12）
node -e "const r=require('./miniprogram/data/recipes.js'),t=require('./miniprogram/data/terms.js');t.forEach(x=>console.log(x.name, r.filter(y=>(y.terms||[]).includes(x.name)).length))"

# 枚举白名单与实际值
node -e "const r=require('./miniprogram/data/recipes.js');const u=a=>[...new Set(a)];console.log('difficulty',u(r.map(x=>x.difficulty)));console.log('evidence',u(r.map(x=>x.evidence)))"

# 食材档案与覆盖
node scripts/build-ingredients.js

# 合规（脱敏词 / 密钥 / BOM）
node scripts/check-compliance.js
```

**字段白名单在代码里**：`miniprogram/utils/dataSource.js` 的 `CUISINES` / `DIFFICULTIES` / `COST_LEVELS` / `ORIGINS` / `EVIDENCE_LEVELS` / `REQUIRED_FIELDS`。改白名单要改那里，不要改数据。
