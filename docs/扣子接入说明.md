# 扣子（Coze）接入说明

> 现状：`utils/config.js` 里 `DATA_CHANNEL = 'local'`、`COZE_CONFIG` 全空，
> 所以生成页的引擎标识显示「本地推演引擎 · 扣子模型未接入」——
> 这是如实标注，不是设计缺陷。下面三步填完，页面会自动切到「Coze Agent · 模型在线」。

---

## 一、为什么现在必须显示「未接入」

生成页的推理轨迹（读节气 → 懂诉求 → 召回 → 剔除 → 排序 → 出菜）**全部是本机规则算出来的真实结果**，
每一条的条数都能在「查看依据」里复算。这一步不依赖模型，也不会因为模型没接就编造。
所以标识必须写清来源：本地推演就是本地推演。

接入后页面会**多出一步「模型复述」**：把这次搭配讲成一句话。规则推演负责「挑得对」，模型负责「讲得顺」，
两者分开，答辩时也好解释。

---

## 二、两种接法，选一种

### 方案 A｜SCF 代理（推荐，前端零 token）

1. 在 `utils/config.js` 填代理地址：

```js
const DATA_CHANNEL = 'coze-proxy';
const API_BASE = 'https://你的代理域名';   // 必须 HTTPS
```

2. 代理侧需要提供 `POST /coze/chat`，入参就是页面发出去的 payload：

```json
{
  "messages": [{ "role": "user", "content": "今日节气：立冬\n口味：清淡\n…" }],
  "stream": false
}
```

3. 代理内部用服务端 token 调扣子开放平台，把返回原文透传回来即可。
   页面能容错识别 `reply` / `answer` / `messages[].content` 三种结构（见 `agent.js` 的 `pickAnswer`）。

4. 微信后台「开发管理 → 服务器域名 → request 合法域名」加上代理域名。

### 方案 B｜前端直连（已移除）

**这方案已经不做了。** 原写法是把 `botId` 与 `apiToken` 写进 `utils/config.js`：

```js
// ❌ 已删除，不要恢复
const COZE_CONFIG = { apiToken: '你的 token', ... };
```

**移除原因**：小程序包可被解包，token 写进前端等同于公开。这与项目「前端零密钥」红线直接冲突，也和微信审核要求不符。

现在 `config.js` 里没有任何 token 字段，`COZE_CONFIG` 整个对象已删掉——留着会诱导后来的人往里填。

## 三、Bot 对话（cloudfunctions/aichat）

工作流是**同步**的，Bot 对话是**异步**的，两条链路完全不同，别混。

### 3.1 三跳流程（少一步都拿不到内容）

```
① POST /v3/chat
   → 返回 { id: 'chat_xxx', conversation_id: 'conv_xxx', status: 'in_progress' }
   ↑ 这里**没有消息内容**，直接读响应体永远是空的

② GET /v3/chat/retrieve?conversation_id=&chat_id=
   → 每 1.2 秒轮询一次，最多 18 次（≈22 秒）
   → 直到 status ∈ { completed, failed, canceled, requires_action }

③ GET /v3/chat/message/list?conversation_id=&chat_id=
   → 过滤 role=assistant && type=answer
   → 这才是用户看到的那句话
```

### 3.2 配置

**Bot ID 已内置**（`cloudfunctions/aichat/index.js`）：

```js
const DEFAULT_BOT_ID = '7709769802239475721';
const BOT_ID = process.env.COZE_BOT_ID || DEFAULT_BOT_ID;
```

填了环境变量以环境变量为准，没填用默认值。

Bot ID 不是密钥——单独泄露无法调用（还要 token）。但仍只放在服务端，**小程序包里不出现**（已核验 0 处命中）。

### 3.3 部署三步

```
① 右键 cloudfunctions/aichat → 上传并部署
② 云开发控制台 → 云函数 → aichat → 配置
     COZE_TOKEN = pat_xxx        ← 必填
     超时       = 60 秒          ← 默认 20 秒不够（三跳 + 轮询最多 22 秒）
③ 小程序首页 → 康康对话 → 发一句话
```

### 3.4 平台侧先验证

部署前先用脚本确认「平台能不能通」，把问题范围缩小：

```powershell
$env:COZE_TOKEN = 'pat_xxx'
node scripts/check-bot.js
```

它会走完三跳，打印每一步的状态。常见错误码：

| code | 含义 | 修法 |
|---|---|---|
| `4100` | token 无效或没授权这个 Bot | 重新生成 token，确认勾了 Bot 权限 |
| `4200` | Bot 未发布 | 扣子后台点「发布」 |
| `4000` | 参数缺失 | 检查 `bot_id` |
| 轮询 18 次仍未结束 | Bot 处理太慢 | 换模型或简化 Bot 流程 |


## 三、改完怎么验

1. 打开「食养 → 生成今日食单」。
2. 页头引擎标识应变成 **Coze Agent · 模型在线**（绿点）。
3. 轨迹最后会多出一步「模型复述」，内容来自模型返回。
4. 模型超时或报错时，会显示「扣子没有响应，本轮回退本地推演」——
   前面的条数与结论照旧可用，不会整页失败。

---

## 四、不要做的事

- 不要为了「看起来像调了模型」而在没接的时候伪造模型输出——这会被评委一眼看穿，也违背 AI4S 的如实披露要求。
- 不要把 `apiToken` 提交进仓库或打包上线。
- 不要让模型输出涉及健康功效表述；prompt 里已显式要求「不作健康或疗效表述」，代理侧最好再加一层过滤。
