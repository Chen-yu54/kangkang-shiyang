# 扣子（Coze）接入说明

> 现状：`utils/config.js` 里 `DATA_CHANNEL = 'local'`、`COZE_CONFIG` 全空，
> 所以生成页的引擎标识显示「本地推演引擎 · 扣子模型未接入」——
> 这是如实标注，不是设计缺陷。下面三步填完，页面会自动切到「Coze Agent · 模型在线」。

---

## 一、为什么现在必须显示「未接入」

生成页的推理轨迹（读节气 → 懂诉求 → 召回 → 剔除 → 排序 → 出菜）**全部是本机规则算出来的真实结果**，
每一条的条数都能在「查看依据」里复算。这一步不依赖模型，也不会因为模型没接就编造。
所以标识必须写清来源：本地推演就是本地推演。

接入后页面会**多出一步「模型复述」**：把这次搭配讲成一句话。规则推演负责「挑得对」，模型负责「讲得顺」，
两者分开，答辩时也好解释。

---

## 二、两种接法，选一种

### 方案 A｜SCF 代理（推荐，前端零 token）

1. 在 `utils/config.js` 填代理地址：

```js
const DATA_CHANNEL = 'coze-proxy';
const API_BASE = 'https://你的代理域名';   // 必须 HTTPS
```

2. 代理侧需要提供 `POST /coze/chat`，入参就是页面发出去的 payload：

```json
{
  "messages": [{ "role": "user", "content": "今日节气：立冬\n口味：清淡\n…" }],
  "stream": false
}
```

3. 代理内部用服务端 token 调扣子开放平台，把返回原文透传回来即可。
   页面能容错识别 `reply` / `answer` / `messages[].content` 三种结构（见 `agent.js` 的 `pickAnswer`）。

4. 微信后台「开发管理 → 服务器域名 → request 合法域名」加上代理域名。

### 方案 B｜小程序直连（仅内部演示）

1. `utils/config.js`：

```js
const DATA_CHANNEL = 'coze-direct';
const COZE_CONFIG = {
  baseUrl: 'https://api.coze.cn/open_api/v2/chat',
  botId: '你的 bot_id',
  apiToken: '你的 token',
  userId: 'anonymous',
};
```

2. ⚠️ 这种写法 token 会随小程序包公开，**只适合本地演示**，不要提交审核、不要公开发布。
   要上线就走方案 A。

---

## 三、改完怎么验

1. 打开「食养 → 生成今日食单」。
2. 页头引擎标识应变成 **Coze Agent · 模型在线**（绿点）。
3. 轨迹最后会多出一步「模型复述」，内容来自模型返回。
4. 模型超时或报错时，会显示「扣子没有响应，本轮回退本地推演」——
   前面的条数与结论照旧可用，不会整页失败。

---

## 四、不要做的事

- 不要为了「看起来像调了模型」而在没接的时候伪造模型输出——这会被评委一眼看穿，也违背 AI4S 的如实披露要求。
- 不要把 `apiToken` 提交进仓库或打包上线。
- 不要让模型输出涉及健康功效表述；prompt 里已显式要求「不作健康或疗效表述」，代理侧最好再加一层过滤。
