> 20 个页面的入口、职责、关键交互与四态覆盖情况。
> 本文所有描述与代码一致，可逐条对照 `miniprogram/pages/` 与 `miniprogram/packageDishes|packageIngredient/`。

## 一、主流程（三条入口，同一个终点）

```
                    ┌─────────────────────────┐
                    │  首页 index              │
                    │  节气主视觉 + 当令菜      │
                    └────┬────────┬────────┬────┘
                         │        │        │
        点节气            │        │ 点「问问康康」  点「康康对话」
                         ▼        ▼        ▼
              ┌──────────┐  ┌──────────┐  ┌──────────┐
              │solarterm │  │ agent    │  │ aichat   │
              │节气详情   │  │对话式问卷 │  │自由对话   │
              └────┬─────┘  └────┬─────┘  └────┬─────┘
                   │             │             │
                   │        6 轮答完          打字提问
                   │             ▼             ▼
                   │      本地推荐 + 工作流  扣子 Bot（三跳）
                   │             │             │
                   └─────────────┴─────────────┘
                                 ▼
                          ┌──────────┐
                          │  dish    │
                          │ 菜谱详情  │
                          └────┬─────┘
                               │ 点主料
                               ▼
                    ┌────────────────────┐
                    │ packageIngredient  │
                    │ 食材档案（分包）    │
                    └────────────────────┘
```

**三条入口的区别**：

| 入口 | 用户动作 | 后端 | 适合谁 |
|---|---|---|---|
| 首页 → 节气详情 | 浏览 | 纯本地 | 只想看看有什么菜 |
| 首页 → 问问康康 | 点 6 次选项 | 本地 + 工作流 | 不知道自己想吃什么 |
| 首页 → 康康对话 | 打字 | 扣子 Bot | 想追问、想自由表达 |

#### 4. `menu` 专属推荐

| 项 | 内容 |
|---|---|
| **入口** | tabBar 第二项 |
| **职责** | 问卷入口 → 6 步推演动画 → 三道菜 + 当令提醒 |
| **关键交互** | `onRunGen` 开始推演 / `onStartQuiz` 去做问卷 / `onTapResultDish` 看菜品 / `onSwitchBrowse` 按菜系浏览 |
| **状态机** | `genState`: `none`（没推演）/ `stale`（答案变了）/ `ready`（有结果）|
| **四态** | ✅ 加载 ✅ 空 ✅ 错误 ❌ 图片失败 |
| **代码** | `pages/menu/`，783 行（最大的页面）|

**20 秒等待用本地推演动画填满**（6 步 × 620ms ≈ 3.7s），模型返回后替换结果。模型未返回时**清空本地菜、挂等待态**，避免用户误以为本地菜就是结果。

#### 5. `agent` 问问康康（对话式问卷）

| 项 | 内容 |
|---|---|
| **入口** | 首页「问问康康」/ 我的页「问问康康」 |
| **职责** | 把 6 道问卷包成对话，点选项答完直接出菜 |
| **关键交互** | `onTapOption` 点选项 / `onNextStep` 多选提交 / `onTapDish` 看菜 / `onRestart` 重来 |
| **状态机** | `stage`: `ask`（答题中）/ `think`（出菜中）/ `result`（已出结果）|
| **后端** | 本地推荐立即出 → 扣子工作流覆盖 |
| **四态** | ✅ 空（无档案时提示）❌ 加载 ❌ 错误 ❌ 图片失败 |

**为什么是脚本化对话而不是自由对话**：问题与选项固定，用户点选不打字。长者不会描述"我想要温润不燥的"，但会点"怕冷"。

### 三个真实缺口（不回避）

**① 图片加载失败态几乎全缺**

只有 `gallery` 页处理了 `binderror`。其他页面用的是 `dishMedia` 组件，组件内部**没有** `binderror` 兜底——图片 404 时会出现碎图或空白。

**② `dish` 页缺空态**

菜谱 id 不存在时会走到错误态，但错误文案不区分"id 无效"和"网络失败"。

**③ `agent` / `aichat` 缺加载态**

两个对话页都是"用户点完立刻有反馈"的交互（点选项→下一条消息，打字→打字动画），所以没做骨架屏。但如果 Bot 响应慢，`aichat` 只有打字动画，没有超时提示——超过 60 秒云函数超时后才报错。

这三条如果要补，改动量：

| 缺口 | 修法 | 工作量 |
|---|---|---|
| 图片失败态 | 在 `dishMedia` 组件加 `binderror` + 占位 | 1 小时（改一处，全站生效）|
| `dish` 空态 | 区分错误码，加专用文案 | 30 分钟 |
| `aichat` 超时提示 | 加 30 秒前端计时器 | 30 分钟 |

## 五、无障碍实现

| 项 | 做法 | 位置 |
|---|---|---|
| 字号自适应 | JS 生成 CSS 变量注入页面根节点 `style` | `utils/theme` + 各页 `pageStyle` |
| 正文 ≥36rpx | 样式常量 | 全部页面 |
| 点击区 ≥88rpx | `min-height: 88rpx` | 按钮、芯片、列表行 |
| 对比度 ≥4.5:1 | 实测值写在注释里 | `disclaimer.wxss` 等 |
| 不靠颜色传信息 | 状态除颜色外都有文字（「已开启 / 未开启」「当前」）| `mine`、`solarterm` |
| 长者模式 | `globalData.elderMode` 隐藏次要入口，一屏少四条可点项 | `mine` |

**为什么字号用 JS 注入而不是 CSS 变量**：`--font-*` 定义在 `page{}` 里是静态的，JS 改 `setData` 影响不到它——这是"字号设置没反应"的高频成因。
